# 美术资产接入（.glb）

**一句话：把 `.glb` 按 id 名字丢进 `assets/models/` 就生效，没有就自动回退程序化模型。**

代码入口：`scripts/art/model_assets.gd`（`ModelAssets`）。单位造型在
`scripts/units/flyer.gd` / `rover.gd` / `unit_models.gd`，建筑在
`scripts/buildings/building.gd`，三处都先问一句「有没有资产」，有就 return，没有才走程序化。

## 目录与命名

```
assets/models/units/<unit_id>.glb        feifei.glb  scout.glb  rover.glb  builder.glb …
assets/models/buildings/<def_id>.glb     miner.glb  factory.glb  turret.glb  charger.glb …
```

- `unit_id` 取自 `data/units/*.json` 的 `id`，`def_id` 取自 `data/buildings/*.json` 的 `id`（比 `kind` 细）。
- 支持 `.glb` 和 `.gltf`；`.gltf` 依赖的 `.bin`、贴图请放同一目录。
- 按名字匹配，**不用改代码、不用改 JSON**。删掉文件即回退程序化造型。
- 进导出包前用 Godot 编辑器导入一次（会让资源进 `.pck`）；没导入的裸文件也能在开发期用
  `GLTFDocument` 直接读，方便美术边改边看。

## 自动处理

| 处理 | 单位 | 建筑 |
| --- | --- | --- |
| 等比缩放 | 最长边贴合基准方盒：悬浮单位 0.75 米、地面单位 1.2 米（= 数据里 `size` 的基准值），外部再按实际 `unit_size` 缩放 | 缩到不超过 `data/buildings` 的占地（略小留边，不放大） |
| 对齐 | 包围盒中心对齐原点（和程序化模型一致） | 底面贴 `y=0`、水平中心对齐原点 |
| 车车上车身高度 | 包围盒最低点对到轮底高度（约 -0.3 基准单位） | —— |

美术只要保证「模型正面朝 -Z、单位尺寸大致方正、建筑底面在 y=0」即可，缩放和对齐由代码兜底。

## 队伍色约定（画风统一的关键）

节点名或材质名里带下面这些词（不区分大小写），代码会给材质的 `albedo_color` 染队伍色：

- `team` → 主体队色：单位蓝方 `#29479e`、红方 `#9e2624`；建筑蓝方 `#3861c7`、红方 `#b8332e`
- `trim` / `accent` → 识别色：单位蓝方 `#47d9f2`、红方 `#fa9e2e`；建筑蓝方 `#59e6ff`、红方 `#ffa838`

其余材质（发光件、玻璃、装饰）原样保留，不加描边也不改色。
染色是 `贴图 × albedo_color`，所以**队色部件请用白色/浅灰占位贴图**，染出来最准；
已经画好固有色、不想被染的部件，名字里别带 `team`/`trim`/`accent`。

## 动画部件（可选，按下面固定名字建就能继续动）

代码会按名字递归找这些节点，找到就接上动画，找不到就静默跳过（资产可以不带）：

| 节点名 | 用在哪 | 效果 |
| --- | --- | --- |
| `Flame` | 悬浮单位 | 喷口火焰，随起飞力度拉长/闪烁 |
| `Radar` | 悬浮单位 | 顶部雷达罩，持续旋转 |
| `Barrel` | 悬浮单位 | 炮管，开火时后退一下 |
| `Wheel_1`…`Wheel_4` | 地面单位 | 轮子按车速转 |
| `Drill` | 建筑 | 钻头旋转（采矿机） |
| `Crane` | 建筑 | 吊臂旋转（组装厂） |
| `Ring` / `Core` / `Dish` | 建筑 | 感应环旋转 / 核心脉动 / 雷达盘旋转 |
| `Smoke` | 建筑 | 烟囱冒烟锚点（空节点即可） |
| `Arm_L` / `Arm_R` | 预留 | 暂未接动画，可先按此命名 |

## 资产规格（和主程既定口径一致）

- 格式：`.glb`（glTF 2.0），**Y 向上、正面朝 -Z、1 单位 = 1 米**
- 原点：单位模型原点放在**底部中心**（代码会自动居中/贴地，放偏了也能救回来，但按这个来最省事）
- 面数：单位 ≤ 1200 三角面，建筑 ≤ 2500 三角面
- 贴图：单张 256~512px 足够；队色部件用白色/浅灰占位，靠 `team`/`trim` 命名染色
- 不要给资产自带碰撞体、灯光、摄像机、脚本；碰撞和逻辑都在代码里

## 碰撞体

仍由代码按数据里的 `size` 建长方体碰撞，**不读资产的碰撞形状**，所以资产是纯视觉，不影响手感和联机一致性。

## 联机与存档

资产只是外观，单位/建筑的快照里只有 id 和队伍，所以主机和客户端装同一套资产即可，
不影响 20Hz 快照格式，不用改协议。
