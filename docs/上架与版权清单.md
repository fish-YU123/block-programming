# 上架 Steam 前的检查清单（本项目当前状态）

> 目的：把"会卡审核 / 会被告 / 会赔钱"的坑提前列出来。发现一项风险就在这里加一条。

## 一、代码与运行环境

- [x] 玩家代码执行改造：**已从 Python 子进程换成本项目自研的沙箱字节码 VM**
  （`scripts/lang/`）。玩家机器不需要装 Python，也不能读文件、联网、起进程。
  - 这是 PVP 游戏的关键：执行别人的代码不再等于把电脑交给对方。
- [ ] 正式版联机前仍要复核：服务端只接受脚本源码/字节码 + 预算限制，
  不能让客户端直接控制他人单位。
- [ ] 建议在发售前对 VM 做一次"恶意脚本"压测（超长字符串、超大列表、
  病态递归、深嵌套调用）。

## 二、美术与素材版权（最容易踩雷）

- [ ] 所有贴图 / 模型 / 音效：确认来源可商用（CC0、OFL、付费授权），
  并把授权记录（购买凭证、许可证文本、来源 URL）存进仓库 `licenses/`。
- [ ] **绝对不要**使用 Minecraft 的名称、贴图、音效、UI 素材，
  也不要使用任何从游戏文件里提取的资源。
- [ ] 方块类游戏视觉风格要"方块感"但不"像 Minecraft 的方块贴图"——
  自己画/自己买，保留创作记录。
- [ ] 字体：中文字体必须商用免费（思源黑体 / 阿里巴巴普惠体 / 站酷系列 / 霞鹜文楷）；
  代码编辑器用 OFL 等宽字体（JetBrains Mono、IBM Plex Mono）。
  **不要**用微软雅黑、苹方等系统字体打包分发。
- [ ] AI 生成的贴图/音频：Steam 强制要求披露，且部分 AI 素材有版权争议，
  建议只用于占位，正式素材转人工或保留完整生成记录。
- [ ] 第三方插件 / GDExtension（如 GodotSteam）：逐个核对 license，
  在 `licenses/` 存档，并在游戏内"关于"页列出。

## 三、名称与商标

- [ ] 游戏名先在 Steam 商店搜索重名，再到中国商标网查是否被注册。
- [ ] 名字不要蹭现有 IP（"××世界""方舟××"之类要格外小心）。
- [ ] 完成后尽快注册自己的商标（至少第 9 类、第 41 类）。

## 四、Steam 平台要求

- [ ] Steamworks 账号 + 100 美元 App 费（卖出 1000 美元后返还）。
- [ ] 商店页：截图、预告片、简介（中英）、系统需求。
- [ ] 隐私政策（如果收集任何数据）、EULA。
- [ ] 成就 / 云存档 / Steam 创意工坊等按需接入 GodotSteam。
- [ ] 内容分级问卷（IARC）如实填写。
- [ ] 上线前至少留 2~4 周做商店页审核 + 愿望单积累。

## 五、本项目已知的技术风险

- [ ] 显卡只有 4GB 显存：开发期建议先用 Compatibility 渲染器，
  或降低地形载入半径，确认帧率后再上调画质。
- [ ] 大量单位 + 100×100 方块场景的物理性能要压测：
  目标 30 / 60 / 100 单位时保持 60 帧。
- [ ] 联机方案：**服务端权威 + 固定 20Hz tick**，
  不要用 Jolt 物理做确定性 lockstep（跨平台浮点不可靠）。
- [ ] 存档/联机协议版本号，避免更新后老存档/老客户端崩溃。
